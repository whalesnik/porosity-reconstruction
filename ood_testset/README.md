# Набор для проверки OOD-детектора

100 срезов: сухой снимок (вход модели), предсказанный ксенон (выход модели) и
фактическая ошибка модели на этом срезе.

```
input_dry/img_000.png … img_099.png    вход модели, 768×768, 16 бит
pred_xenon/img_000.png … img_099.png   выход модели, тот же срез
labels.csv                             метрики и происхождение
```

**Файлы пронумерованы вперемешку.** Происхождение среза есть только в `labels.csv`.
Сделано намеренно: по именам вида `sk_*` / `un_*` детектор можно нечаянно
настроить, и проверка перестанет что-либо значить.

Половина срезов — сколтеховский керн, на котором модель обучалась (взяты
отложенные срезы z 720…900, при обучении не использовались). Половина —
университетский керн 22322-24, которого модель не видела вовсе.

## PNG без нормировки

16 бит, сырые единицы КТ, как их выдаёт прибор. Приводить оба образца к одной
шкале нельзя: разница шкал и есть тот сигнал, который канал условий съёмки
должен ловить. Если нормировка нужна, константы в `labels.csv`:

```python
x = (img.astype("float32") - offset) / scale
```

Оба образца обрезаны до 768×768 из центра, чтобы размер совпадал. **Размер вокселя
при этом разный: 3.000 мкм против 3.690.** Это настоящее свойство данных, а не
недосмотр — структурный канал должен на него реагировать.

## Какую ошибку предсказывать

В `labels.csv` пять кандидатов, и они ведут себя совершенно по-разному:

| колонка | Сколтех | Университет | AUROC |
|---|---|---|---|
| `phi_abs_error` | 1.00 [0.04; 1.42] | 1.21 [0.09; 3.30] | **0.625** |
| `phi_bias` | −1.00 | −1.13 | 0.602 |
| `mae` | 5.93 [5.75; 6.39] | 14.09 [12.18; 15.81] | **1.000** |
| `rmse` | 9.16 | 18.35 | 1.000 |
| `pearson` | 0.89 | 0.82 | 0.991 |

AUROC здесь — насколько метрика сама по себе разделяет два образца.

**`mae`, `rmse` и `pearson` разделяют идеально, но это лёгкая победа.** Они почти
целиком определяются шумом эталона: σ_φ = 3.5 п.п. на сколтеховском скане и
12.9 на университетском. Детектор, который их предсказывает, обнаруживает
«другой прибор», а не «модель ошиблась». Для канала условий съёмки это законная
и полезная цель, но заявлять по ней качество детектора как целого нельзя.

**`phi_abs_error` — трудная и содержательная цель.** Это промах по интегральной
пористости, то есть ровно та величина, ради которой всё делается. И она почти
не растёт за пределами обучающего домена: 1.00 против 1.21 п.п., AUROC 0.625.

## Что из этого следует

Модель на чужом керне ошибается по интегральной пористости лишь немногим
сильнее, чем на своём. Значит **срабатывание OOD-детектора на этом образце,
использованное как повод отвергнуть предсказание, было бы ложной тревогой** —
предсказание там годное.

Отсюда практический вывод: детектор полезен не как переключатель «верить / не
верить», а как оценка того, **насколько** упадёт точность и **какая именно**.
На этом образце падает локальная точность (MAE вдвое), а интегральная почти нет.
Полезная форма результата — не «OOD: да/нет», а две калибровочные кривые:
скор → ожидаемый промах по пористости и скор → ожидаемая локальная MAE.

## Ограничение набора

Здесь только две точки по оси «похожесть»: свой керн и один чужой. Кривую по двум
точкам не построить. Чтобы получить промежуточные, можно взять сколтеховские
срезы и применить к ним **контролируемые искажения** — сдвиг яркости, изменение
усиления, шум заданной величины, размытие, — прогнав модель заново. Истина там
известна, искажение задано, и точек получится столько, сколько нужно.

## Колонки labels.csv

| колонка | что это |
|---|---|
| `id` | имя файла в `input_dry/` и `pred_xenon/` |
| `sample` | `skoltech` или `university` — **ответ, не подавать в детектор** |
| `z` | номер среза в исходном объёме |
| `voxel_um` | размер вокселя, мкм |
| `phi_abs_error` | \|φ предсказанная − φ эталонная\|, процентные пункты |
| `phi_bias` | то же со знаком |
| `phi_pred`, `phi_real` | пористость среза, % |
| `mae`, `rmse` | повоксельная ошибка φ-карты, п.п. |
| `pearson` | корреляция предсказанной и эталонной φ-карт |
| `sigma_phi_noise` | шум эталона для этого образца, п.п. |
| `offset`, `scale` | константы нормировки для сети |
| `beta`, `d100` | константы калибровки, φ = (I_xe − I_air + β) / ΔI₁₀₀ × 100 |

Собрано скриптом `make_ood_set.py`, модель `2d_unet_l1` (2D U-Net, эпоха 22).
