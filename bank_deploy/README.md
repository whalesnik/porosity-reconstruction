# Рабочий детектор: банк и модуль

Всё, что нужно для проверки нового среза. **61 МБ**, процессора достаточно.

```
structure_bank.f16    61.4 МБ   200 срезов × 200 патчей × 768, float16
acquisition_bank.npy  0.05 МБ   200 гистограмм яркости
calibration.json                пороги, откалиброванные по 120 отложенным срезам
meta.json                       все константы
guard.py                        модуль проверки
```

Полный исследовательский банк (6 ГБ, 900 сухих + 900 ксеноновых срезов) в работе
не нужен: exp10 показал, что качество шкалы выходит на потолок к 200 срезам
одного образца, а exp16 — что ксеноновый банк для различения доменов бесполезен
(AUROC 0.460).

## Как пользоваться

```python
from guard import Guard

g = Guard()                      # ~5 с, один раз
r = g.check(slice_2d)            # ~0.7 с на срез (0.5 с сеть + 0.2 с поиск)

r.acquisition_trust   # 0..1
r.structure_trust     # 0..1
r.verdict             # текст
r.structure_map       # 32×32, где именно непохоже
```

Вход — сырой срез в единицах КТ, не меньше 448×448 (берётся центральная область).

Если известна собственная яркостная шкала нового образца, лучше её передать:
`g.check(img, own_window=(lo, hi))`. Структурный канал тогда считается в этой
шкале, и связь с локальной точностью выходит заметно сильнее (ρ +0.40 против
+0.29 на чужом керне). Канал условий съёмки всегда считается в шкале обучающих
данных — иначе он по построению перестал бы видеть смену прибора.

---

## Что означают два числа

### `acquisition_trust` — похожи ли условия съёмки

Считается по гистограмме яркости. Отвечает на вопрос «тот же прибор и настройки?».
К структуре породы почти слеп по построению (AUROC 0.536 на тесте, где гистограмма
сохранена, а пространственная связность разрушена) — и это его роль, а не изъян.

**Сработал** → данные снимали иначе. Перенормировать вход перед подачей в модель.
Порода при этом, скорее всего, та же.

### `structure_trust` — похожа ли порода

Считается по патч-токенам DINOv2. Отвечает на вопрос «тот же тип породы?».
К равномерному сдвигу яркости почти нечувствителен: сдвиг +0.20 даёт
`acquisition_z` +375 при `structure_z` +2.1.

**Сработал** → порода незнакомая. Локальная точность реконструкции ожидаемо ниже.

### Почему два числа, а не одно

Реакция команды на эти случаи противоположна: смена прибора лечится
перенормировкой, смена породы — нет. Одно число не позволяет выбрать действие.

Проверка разделения на данных Сколтеха:

| Случай | съёмка (z) | порода (z) |
|---|---|---|
| знакомый срез | −0.0 | −1.2 |
| яркость +0.20 | **+375** | +2.1 |
| блоки перемешаны (гистограмма сохранена точно) | +0.2 | **+11.6** |

---

## Чего эти числа НЕ означают

**Это не вероятность того, что предсказание пористости верно.**

Проверено на двух наборах с реальными парами «снимок и ошибка модели»
(`ood_testset`, `ood_testset_univ`): связи скора с промахом по интегральной
пористости нет ни на одном образце, p от 0.19 до 0.92. Не появляется она и после
вычитания систематического смещения модели.

Причина установлена: на чужом керне модель почти не реагирует на изменение
истинной пористости — наклон отклика 0.093 вместо 1.0, разброс предсказания
0.247 п.п. при разбросе истины 1.188 п.п. Ошибка задаётся истиной, а не входом,
поэтому предсказать её мог бы только детектор, умеющий сам оценивать пористость.

**Что числа означают на самом деле:**

| Вопрос | Ответ детектора |
|---|---|
| данные за пределами обучающих? | да, надёжно (AUROC 1.000) |
| какая ожидается локальная точность? | ранжирует, но слабо (см. ниже) |
| верна ли будет цифра пористости? | **сказать нельзя** |

---

## Насколько сильна связь с локальной точностью

Ранговая корреляция скора с попиксельной ошибкой φ-карты, внутри образца:

| Образец | ρ | ρ с поправкой на глубину |
|---|---|---|
| Сколтех | +0.567 | +0.469 |
| университетский керн | +0.399 | +0.351 |

Воспроизвелось на двух независимых кернах — связь настоящая. Но по величине она
скромная: переход от лучшей трети срезов к худшей меняет MAE всего на **4 %**
(Сколтех) и **10 %** (университет).

То есть ранжировать срезы по ожидаемой локальной точности можно, а обещать
существенную разницу — нет.

## Пороги и ложные срабатывания

Пороги заданы в единицах разброса калибровочной выборки:

- `z > 3` — предупреждение;
- `z > 6` — тревога.

Порог `доверие < 0.05` соответствует `z > 1.96` и **по построению** отсекает
около 5 % знакомых данных. Измерено: 6 из 120 отложенных срезов (5 %). Это
свойство квантильного порога, а не дефект — увеличение банка его не убирает
(проверено в exp10 на банках от 20 до 800 срезов).

Хотите меньше отказов — поднимайте порог, ценой пропуска пограничных случаев.

## Калибровка

Считается по 120 срезам Сколтеха, **не входящим в банк**. Это важно: калибровка
leave-one-out по срезам самого банка методически хуже, поскольку в банке остаются
почти идентичные соседи по глубине, которых у нового среза может не быть.
На практике обе оценки совпали (0.1854 против 0.1854), но правильная процедура
надёжнее и опирается на большую выборку.

| Канал | среднее | разброс |
|---|---|---|
| структура | 0.1854 | 0.0182 |
| съёмка | 0.000562 | 0.000718 |

## Пересборка под новые обучающие данные

Когда основная модель будет обучаться на другом наборе, банк надо пересобрать —
он должен состоять из тех же данных, на которых учится модель:

```bash
cd ../test-dino
python exp09_build_full_bank.py       # полный банк, ~50 мин
python exp17_export_deploy_bank.py    # выжимка 200×200, ~7 мин
python exp18_recalibrate_holdout.py   # пороги по отложенным, ~2.5 мин
```

Обучения нет ни на одном шаге, только прогон через замороженную сеть.
